Email Personalization Widget

Owner: Technical Services / Staffbase Labs  |  Status: Reference  |  Last reviewed: June 2026

Summary. Staffbase Email ships a native personalization capability (Core: names; Advanced Plan: custom-data personalization via CSV). Where the native feature falls short — most commonly the requirement to upload a CSV instead of reading stored profile fields — Technical Services can deliver a custom widget. The best-documented variant is the Email Signature Generator, which auto-populates a signature from a user's Staffbase profile. This page covers the native feature, its known limitation, the custom widget spec and pricing, the widget framework, and known edge cases.

1. Native Platform Feature: Email Personalization (Advanced Plan)

Staffbase Email has a built-in personalization capability that is part of the Advanced Plan:

"Advanced Personalization: Tailor every email with custom tags and CSV-uploaded data to reach the right people, make content feel personal, and increase engagement."

Key capabilities

2. Known Limitation: Profile Field Personalization

The native personalization requires uploading a CSV. Customers have repeatedly asked that it pull directly from stored user profile fields instead.

"Email personalization — we shouldn't have to upload a new list to use this feature. We're already storing information in our Atlas user profiles — why does this feature not pull from there?"

Custom profile-field segmentation and personalized targeting is on the 2026 Email roadmap as a strategic initiative. Until that ships, the custom widget below is the workaround for profile-driven personalization in page contexts.

3. Custom Widget Version: Email Signature Generator

The most well-documented custom widget variant is the Email Signature Generator, scoped and delivered by the Labs / Technical Engineering team. It generates a personalized email signature for each user, auto-populated from their Staffbase profile fields.

How it works

  1. Widget config includes upload fields for English and German HTML templates.
  2. A mapping section lets editors define each placeholder (e.g. {{firstName}}) and map it to the corresponding Staffbase profile field ID.
  3. When a user opens the page, the widget fetches their profile data, injects mapped values into the template, and renders the final signature — no manual input needed.
  4. A language selector lets users toggle between English and German versions.
  5. A Copy button copies the rendered HTML signature to the clipboard for pasting into any email client (Outlook, Apple Mail, etc.).

Out of scope: Central event/banner selector (trade shows, seasonal campaigns) — would require a backend storage layer not available in the widget framework.

Customer responsibilities

  • Prepare HTML signature templates with placeholder tokens (e.g. {{placeholder_name}}).
  • Ensure all required profile fields are populated for all users.
  • Provide a test account with representative profile data.
  • Provide feedback within 30 days of delivery.

4. Custom Widget Framework (Technical Context)

  • Custom widgets are built using the Widget SDK (~30 KB Web Components).
  • Per-user personalization is handled via JWT.
  • The Staffbase Labs Custom Widget Collection (staffbase.github.io/solutions-monorepo) is a live gallery of all pre-built custom widgets.
  • An AI-powered widget builder is available internally — describe the widget in plain English, refine via chat, and download a ready-to-use .min.js file.

5. Known Behavior / Edge Cases

AreaBehavior
CC functionalityNot supported. A recipient either receives the email or doesn't — there is no way to CC an additional address.
Personalization widget in JourneysCurrently works only for Push notifications, not Email notifications within Journeys.
CSV identifier columnMust match the user's email address or their internal/external Staffbase ID.
